# 日志与测试数据解析指引

HIL / MIL / 整车实验/标定问题的附件 logs 常见格式与读取套路。按需使用，不写死工具链。

## 一、常见格式与读取方法

| 格式 | 来源工具 | 读取方法 |
|---|---|---|
| `.asc` | **CANoe** 日志（CAN/LIN 文本） | 文本；行格式 `时间 通道 ID 方向 DLC 数据`；按 ID 过滤目标报文，解析信号需 DBC |
| `.blf` | **CANoe** 二进制日志 | `python-can`（`can.io.BLFReader`），或让用户在 CANoe 里导出 CSV 后读 |
| `.mdf` / `.mf4` | **CANape** / ASAM 测量文件（INCA 等通用） | `asammdf` 库：`MDF(path)` → `mdf.channels_db` 看信号清单 → `select(信号名)` |
| `.dat` | **CANape 专有**测量格式（旧版） | 第三方库读不了，让用户用 CANape 导出为 `.mf4` / `.csv` 再分析 |
| `.rec` | **CANape** 旧版记录格式 | 同上，导出后读 |
| `.csv` / `.txt` | CANoe / CANape 均可导出 | 文本读取；首行通常是信号名表头，时间列定位 |
| `.cfg` | CANoe 工程配置 | 查报文配置、DBC 关联、通道/网络映射（不是数据文件） |
| `.cnp` / `.ini` | CANape 工程配置 | 查测量配置、通道定义（不是数据文件） |
| 文本报错日志 | 测试台架 / HIL 控制台 | 先 grep 关键字：`error`、`fail`、`assert`、报错码、时间戳段 |

## 二、CANoe / CANape 报文解析套路（问题附件的常见主力）

1. **先分清文件类型**：`.asc`/`.blf` 是**总线报文日志**（看信号通信），`.mdf`/`.mf4`/`.dat` 是**测量数据**（看内部信号/标定量）。两类证据用途不同。
2. **报文日志（.asc/.blf）**：
   - `.asc` 每行一条报文：`时间 通道 ID 方向 DLC 数据字节`；先用上下文 `04_Interface/` 的 DBC 把 ID 翻译成报文名/信号名，再分析。**DBC 是报文类问题的条件必需上下文：附件里有报文而上下文缺 DBC 时，先向用户索要，不要硬猜 ID 含义。**
   - 区分**周期报文**（固定周期发送，如 10ms/100ms）与**事件报文**（条件触发）——周期报文直接看信号值变化，事件报文看触发时刻。
   - 关注"谁先变"：同一现象相关的几个报文/信号放同一时间轴，看跳变先后（服务归因方向判断）。
3. **测量数据（.mf4/.dat）**：
   - `.mf4` 直接用 `asammdf`：先 `channels_db` 列信号名，再 `select` 目标信号做趋势。
   - `.dat`/`.rec` 无法直接解析：**提醒用户用 CANape 导出为 .mf4/.csv**（File → Export），再继续。
4. **时间对齐**：`.asc` 时间戳默认秒（CANoe 可配置），`.mf4` 是微秒/纳秒——多文件对比前先统一时基（相对时间 0 或绝对时间戳），确认采样率/周期差异。
5. **圈定时间段**：按问题复现时刻前后（如报错前后 10s）裁剪数据，缩小检索范围；找关键信号跳变时刻做事件锚点。
6. **画趋势对照**：把"输入/使能/状态/输出"放同一时间轴（Python matplotlib 或 MATLAB），看谁先变、谁跟着变。

## 三、判定辅助

- **报错码/故障码（DTC）**：查需求/诊断文档（如 `Diag.sldd`、DTC 表）翻译成含义。
- **HIL/MIL 差异**：同一问题在 MIL 与 HIL 表现不同 → 优先怀疑测试环境（模型在环激励、总线仿真、IO 映射），再怀疑软件。
- **标定实验**：整车标定问题（如某参数调不动）→ 检查标定量是否被代码强切/覆盖（示例：模式强切逻辑覆盖了标定下限，导致标定参数调不动）。

## 四、注意事项

- 大文件先抽样读（前 N 行/按时间切片），不要一次性全量加载。
- 时间戳单位先确认（秒/毫秒/微秒/内部计数），换算统一。
- 日志中文乱码：检查编码（GBK/UTF-8），代码文件同理。
- 结论必须能在日志里复现（时间点 + 信号值），写报告时引用时间段。
