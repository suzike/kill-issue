# 排查方法库（通用套路）

从真实案例沉淀的排查套路，按问题类型选用。套路是"怎么找"，结论随问题变。

## 1. 三角交叉验证：模型 × 生成代码 × 标定

任何问题先建三条证据线，互相印证：

- **模型（SLX/子系统 xml）**：看逻辑意图、子系统层级、状态机。
- **生成代码（*_autosar_rtw/）**：以它为准——它是实际刷写软件。模型与代码版本不一致时以代码为准。
- **标定（sldd/a2l/代码常量）**：阈值、增益、下限、死区等数值，解释"为什么是这个值"。

套路：先在代码里定位（好检索、有行号），再回模型找对应子系统（出截图），最后用标定值解释行为。三者对不上时，差异本身就是线索。

## 2. 输入链路反推法（信号/状态/请求类）

从输入到处理逻辑逐级反推，每级记录证据位置：

```
输入（RTE/端口/报文信号）
  → 滤波/量纲转换
  → 中间量（无业务名的临时变量）
  → 处理函数（按键/请求处理，输出使能脉冲）
  → 状态机 / 处理逻辑（主状态 / 子状态机）
  → 输出（显示、执行器命令）
```

要点：
- 按键/请求检测多是**单周期脉冲**（变化沿）；"更新标志"与"请求值"语义不同，要区分。
- 同一更新标志/触发信号可能被多个处理函数共用，先查共用再下结论。
- 显示/状态输出一般是"当前状态 == 某状态"的比较结果，直接反推状态机进入/退出条件。

## 3. 状态与显示类问题套路（状态灯、模式、互斥、档位等）

1. 先定位**显示/状态输出信号**（灯、模式、状态值）→ 反推它依赖的状态变量。
2. 进状态机找该状态的**进入/退出条件**（case 分支的 else-if 链）。
3. 逐条反向追退出信号的来源（OR 合并了哪些触发源）。
4. 显示/状态异常常见三类：多个按键共用同一触发信号（OR 合并）、外部联动连带触发（一个操作连带触发了别的请求）、退出信号同时服务多个状态。

## 4. 控制链闭环分析法（PID/执行器/转速类）

现象是"某物理量不收敛/调不动/一直升"时，画控制闭环：

```
输入（目标量）→ 误差 → PID（增量式：Δu = (Kp+Ki+Kd)e_k − (Kp+2Kd)e_{k−1} + Kd·e_{k−2}）
  → 执行器（阀/膨胀阀/电机/转速等）→ 被控量（温度/压力/开度/位置）→ 反馈回误差
```

要点：
- **先确认执行器状态与 PID 使能是否脱钩**（经典缺陷：阀已强制关闭/切换，但 PID 使能仍为 true，积分项持续输出）——案例 001 的根因即此。
- 转速/输出合成看升速/降速分支：任一通道为正即取 max 升速时，其他通道的降速需求被掩盖。
- 误差无法消除时积分项不收敛 → 输出线性冲上限：查抗积分饱和、误差限幅、DeadBand。
- "调不了"先查：目标量是否真的进了控制环（可能被模式强切到别的控制量，如某个阀从温度控制被强切成另一种控制模式）、下限/起始值是否钳制。

## 5. 配置差异法（车型配置、功能开关类）

要求"两种配置都测"时：
- 先查关键路径上有没有 `Configure_*`（或等效配置参数）分支。
- 有分支：分别走两路，逐点对比差异，结论要分配置写。
- 无分支：各配置行为一致，可一并下结论（示例：空调项目案例中 A/C 使能→退 MaxHeat 路径无配置分支，两种车型配置结果一致）。

## 6. 需求比对法（需求类问题）

- 找需求文档对应章节的**原文**，逐句对照实现（模型/代码）。
- 差异分两种：实现偏离需求（软件/模型问题）vs 需求本身不清/矛盾/缺失（需求问题）。
- 需求有歧义时，把两种解读都写出影响，归"待产品确认"。

## 7. 日志时序归因法

- 用时间轴把输入/使能/状态/输出对齐（见 log-reading.md）。
- 归因方向判断：**谁先变、谁跟着变**。先变的是触发源，后变的是被触发。
- 归因示范（空调项目案例）：不是"后空调 AUTO 状态"踢掉 MaxHeat，而是它连带触发了 A/C 使能，撞上"A/C 键按下 → 退 MaxHeat"的老规则——归因要归到真正的触发源，而不是表象状态。

## 8. 版本与一致性核对

- 报告必须记录：软件版本、模型版本、标定版本、构建时间。
- 现象与代码行为对不上时，先怀疑版本不一致（模型旧/代码新、标定没刷进去）。

## 9. 常见坑清单

- 生成代码中间信号（示例：空调项目的 `LogicalOperator*`、`Switch2_*`）无业务名：必须读赋值/使用上下文判断语义，报告里给语义翻译。
- 枚举值（如 `EM_ValveSts_Auto`）在 .h 里可能搜不到定义（来自数据字典/Simulink 枚举）：按上下文判断或查 sldd。
- 代码注释 GBK 编码，grep 中文乱码属正常，改用英文关键字或按行号读。
- 模块内部只读不写的输入信号，联动来源在外部控制器/面板——归"其他"层并列入遗留确认点。
